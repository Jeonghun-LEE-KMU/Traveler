# PR47 정훈 담당 작업 및 PM 인수인계

## 1. 범위와 현재 상황

PR47은 #45·#46 변경을 통합하고, 장소의 이동+체류 예상시간이 사용자 가용시간을
넘는지 확인하는 작업이다. 2026-09-17 사용자 요청에 따라 후속 수정 범위를
**이정훈 담당 업무와 PR47 리뷰 대응**으로 한정했다.

남긴 내용은 장소 수·시간·교통수단 해석, 최종 응답과 오류 계약,
응답 샘플, TC07 통제 응답, 관련 회귀 테스트다.

다현 담당 프론트 구현은 전부 철회했다. 가영 담당 좌표 감사 도구·지도 시간 비교
양식과 프론트 재입력 흐름을 위한 빈 코스 전용 목적지 보존 기능도 철회했다.
프론트 게시를 기다리는 상태가 아니며, 이 문서를 근거로 이전 프론트 bundle을
적용하면 안 된다. 수연 담당 테스트 서버 배포나 실데이터 수정은 수행하지 않았다.

서버 계약만으로 화면 연동이 끝나는 것은 아니다. 다현 담당 구현과 통합 검증은
별도 작업으로 남아 있다. 이 작업에서는 PR 머지와 운영 배포를 하지 않는다.

## 3. 이번에 남긴 수정

- 일반 추천은 3~5곳이다. 명시한 총량·시간 부족·후보 부족은 예외이며 시간이 우선한다.
- `카페 1곳 추가`, `총 2곳만 빼줘`, `맛집 2개 포함`, `5개월`을 전체 장소 수로
  오인하지 않도록 했다. 수정 결과에 최소 3곳을 강제로 다시 채우지 않는다.
- `30분`, `1.5시간`, `4시간 30분`, `1시간 반`을 각각 30·90·270·90분으로 처리한다.
  가용시간 범위는 정수 분 기준 1~720분이다. 이동시간·거리·예약 시점은 구분한다.
- 기차/KTX/SRT와 버스킹을 구분한다. 대중교통·혼합·미지원 이동수단의 이동시간은
  미검증으로 남기며, 이동수단 미지정에 따른 자차 가정은 안내에 표시한다.
- 추가/교체에도 동일한 카테고리별 체류 기본값을 쓰고, 시간 초과로 제외한 사유를 표시한다.
- 출발 GPS와 지역 검색 중심점을 구분한다. 출발 GPS가 없으면 시간은 미검증이며,
  장소 자체의 유효한 좌표까지 지우지는 않는다.
- 빈 최종 결과는 서버에 저장된 이전 코스를 지운다. 빈 결과 전용 목적지 기억 기능은 없다.
- `구성: 장소 3~4곳`처럼 프론트가 붙인 문구도 서버 입력에 포함된다. 사용자가 직접
  지정한 조건과 구분할 수 없으므로, 해당 문구의 제거 여부는 프론트 담당자와 합의한다.

## 4. 최종 메시지와 오류 계약

[응답 샘플 JSON](fixtures/final_response_samples.json)에 정상, 추천 불가, 미검증,
입력 오류 4종이 있다. 합성 후보를 실제 일정 검증·직렬화 함수에 통과시킨 출력이며,
**실제 LLM이나 배포 서버에서 받은 응답은 아니다.**

정상 최종 SSE 데이터는 `recommended_places`와 null이 아닌 `time_budget`을 가진다.
장소 목록이 비어 있어도 `time_budget`이 있으면 확정 결과다.

| 상태 | 의미 |
|---|---|
| `within_budget` | 예상 이동+체류 합계가 예산 이하 |
| `unverified` | 좌표/이동수단 정보 부족; 이동·총합은 null이며 0분이 아님 |
| `no_feasible` | 시간 안에 남길 코스가 없어 빈 배열과 이유를 반환 |

출발지→첫 장소와 장소 사이 이동은 포함하고, 마지막 장소 이후 복귀는 제외한다.
좌표 직선거리와 평균속도에 따른 추정이며 도로·교통·주차를 반영하지 않는다.

`GET /api/chat`의 자연어 입력 오류와 생성 실패는 HTTP 200 SSE 안에서 다음처럼 보낸다.

```text
event: application_error
data: {"error":{"code":"INVALID_REQUEST","message":"사용자 안내 문구","retryable":false}}
```

생성 실패는 `GENERATION_FAILED`, `retryable: true`다. 내부 예외는 노출하지 않는다.
라우트 진입 전 필수 쿼리 누락이나 숫자 형식 오류는 FastAPI의 HTTP 오류로 남는다.
`POST /api/chat/revise`는 잘못된 가용시간에 HTTP 422 + `detail`, 저장 코스 없음에
HTTP 404 + `detail`을 사용한다. 422 오류로 이전 코스를 바꾸지는 않는다.

클라이언트의 정상 종료·빈 카드/핀 정리·재입력 UI·오류 이벤트 처리 요구사항은
[CourseJSON 계약](coursejson-spec.md)을 참고한다. **계약 문서이지 프론트 구현 완료 보고가 아니다.**

## 5. TC07 및 응답 계약의 로컬 재현

백엔드 의존성이 설치된 환경에서 실행한다.

```bash
python -m uvicorn scripts.pm_fixture_server:app --host 127.0.0.1 --port 8765
```

이 서버는 정훈 담당 통제 응답 제공용이다. 운영 앱과 분리되어 있으며
LLM·RAG·DB·실제 길찾기를 호출하지 않는다. 프론트 전용 프록시도 제공하지 않는다.

정상 응답을 만들고, 같은 세션의 수정 결과를 추천 불가로 만드는 예시다.

```bash
curl -N -G 'http://127.0.0.1:8765/api/chat' \
  --data-urlencode 'user_message=경주 4시간 코스' \
  --data-urlencode 'session_id=pm-tc07' \
  --data-urlencode 'lat=35.856' --data-urlencode 'lon=129.224'

curl -sS -X POST 'http://127.0.0.1:8765/api/chat/revise' \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"pm-tc07","user_message":"테스트: 추천불가 1시간 코스"}'
```

| 확인 목적 | fixture 입력/조건 | 기대 결과 |
|---|---|---|
| 정상 | `경주 4시간 코스`, 위 출발 좌표 | 합성 장소 4곳, `within_budget` |
| TC07A 새 생성 | GET의 메시지를 `테스트: 추천불가 1시간 코스`로 변경 | 모든 후보 체류 480분 → 빈 배열, `no_feasible` |
| TC07B 수정 | 정상 GET 후 같은 세션에 위 POST | 빈 배열, `no_feasible`, 저장 코스 제거 |
| GPS 누락 | 정상 GET에서 lat/lon 생략 | `unverified`, 유효한 장소 좌표는 유지 |
| 분/소수 | `1.5시간 코스` | 예산 90분 |
| 입력 오류 | `0분 코스` | GET은 `application_error`, POST는 422 `detail` |
| 생성 오류 | GET에 `테스트: 오류` | `GENERATION_FAILED` |

`테스트:` 문구는 이 로컬 fixture만의 제어값이며 운영 기능이 아니다.
빈 결과 후에는 저장 코스가 없으므로 목적지와 조건을 포함한 새 GET 요청을 사용한다.
이 fixture는 자연어 장소 편집 분류나 실제 후보 품질을 검증하지 않는다.

## 6. 검증 결과와 남은 사항

- 철회 후 백엔드 전체 회귀 테스트: **450 passed**, 기존 deprecation 경고 3건.
- Python compileall 및 `git diff --check` 통과.
- 응답 샘플과 fixture 실제 출력의 일치 여부도 테스트에 포함한다.
- 이전 프론트 빌드·브라우저 검증 결과는 철회된 구현의 결과이므로 현재 인수 근거로 쓰지 않는다.

**NOT RUN:** 배포 URL 통합 검증, 실제 LLM 전후 품질 평가.
좌표 실데이터 점검·지도 이동시간 실측·프론트 화면 검증은 각 담당자의 별도 작업이다.

정훈/PM의 실제 LLM 비교는 후보·좌표·모델·temperature를 고정한 질의 세트로 진행한다.
전체 수/부분 편집 오해, 후보 밖 ID, 검증 가능한 코스의 예산 초과,
fallback·unverified·no_feasible 비율을 기록하고 요청 의도·카테고리 충족도 함께 판단한다.
현재 자동 테스트 통과를 실제 추천 품질 향상의 증거로 해석하지 않는다.
