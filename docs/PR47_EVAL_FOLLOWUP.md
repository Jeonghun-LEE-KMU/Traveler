# PR47 후속: 평가 입력과 시간 예산 계약 정리

작성일: 2026-09-19. 범위는 이정훈 담당 평가 코드와 PR47 리뷰 대응이다.

## 무엇을 고쳤나

[PR47](https://github.com/Traveler-map/mobility_rag/pull/47)은 `develop`에
머지됐다(`c719be6`). 이번 변경은 그 위에 올리는 별도 후속 작업이다.
프론트, 실데이터, API 응답 계약, 운영 배포는 수정하지 않는다.

서비스 생성 프롬프트는 이미 후보 좌표를 사용하지만, 평가 프롬프트에는
`distance_min`을 `이동 N분`으로 표시하는 코드가 남아 있었다. 이 필드는
현재 검색기에서는 km이므로 이동 시간의 근거로 사용할 수 없다.

평가 프롬프트를 `v1.1`로 올리고 다음을 반영했다.

- 유효한 후보 좌표만 표시하고 없거나 잘못된 좌표는 미확인으로 표시한다.
- 지역 검색 중심과 명시된 일정 출발지를 구분한다. 검색 중심을 실제 GPS라고 쓰지 않는다.
- 가용 시간은 `duration_minutes`를 우선한다. 미지정 기본 범위는 서비스와 같은 3~5시간이다.
- 평가 입력에 `duration_hours`만 명시돼 있으면 고정 시간으로 읽는다.
  예를 들어 2시간에 기본 하한 3이 붙어 `3~2시간`이 되는 것을 막는다.
  입력에 명시된 시간 범위는 유지하며 원본 JSONL이나 운영 입력 처리는 변경하지 않는다.
- 서버가 준 `time_budget`의 상태, 이동·체류·합계, 이유를 평가 모델에 전달한다.
  null 시간은 0분이 아니라 미확인이다. 좌표 기반 예상치이며 복귀 이동은 제외됨을 표시한다.
- 평가 모델이 미확인 이동·도로 시간을 만들어 내지 않도록 안내한다.

## 예전 점수와 비교할 때 주의할 점

입력 정보가 바뀐 평가 모델의 점수를 예전 점수와 바로 비교하면,
추천 품질 변화인지 평가 기준 변화인지 구분할 수 없다.

새 baseline에는 `_meta.judge_prompt_version`을 저장한다. 실제 채점 점수를
비교할 때 이 값이 없거나 현재 버전과 다르면 델타를 계산하지 않고
`INCONCLUSIVE`(판정 불가, 종료 코드 2)로 남긴다. 같은 버전의 baseline이면
기존 하락 기준을 그대로 적용한다. 구조 검증 실패는 여전히 `FAIL`이 우선한다.
버전이 같아도 비교할 모드·축의 baseline 점수가 없으면 판정 불가 사유를 남긴다.
비교 가능한 다른 축에서 실제 하락이 확인되면 해당 실행은 `FAIL`이다.

예전 baseline에 버전 문자열만 붙이면 안 된다. 비교 대상 코스를 같은 평가
프롬프트로 다시 채점해야 한다. 후보·좌표·질의·모델·temperature도 동일하게
고정해야 공정한 비교가 된다. 코드가 자동으로 확인하는 것은 평가 프롬프트 버전이며,
나머지 실행 조건의 일치 여부는 별도로 확인해야 한다.

## 검증 범위와 아직 남은 일

이번 자동 테스트는 외부 LLM·DB 호출 없이 입력 문자열과 판정 로직을 검증한다.
실제 LLM 전후 추천 품질 비교를 실행하거나 점수 향상을 확인한 것은 아니다.

- 로컬 전체 테스트: **501 passed**, 기존 deprecation 경고 3건.
- Python 소스 컴파일과 `git diff --check` 통과.
- 독립 리뷰에서 추가 수정 사항 없음. CI와 운영 배포는 별도 상태로 확인한다.

저장소의 `eval/cases.jsonl`에는 60개 케이스와 270개 후보가 있으나,
270개 후보 모두 `lat/lng`가 없고 60개 케이스 모두 명시된
`schedule_origin_lat/lng`가 없다. 검색 중심 좌표는 실제 출발 GPS의 증거가 아니다.
추적되는 실제 baseline·평가 report도 없어, 이 자료만으로 좌표 기반 동선 검증이나
전후 품질 개선을 입증할 수 없다. 이번 작업에서는 좌표나 평가 결과를 만들어 넣지 않았다.

또한 `eval/metrics.py`의 기존 `estimated_total_min`과 `time_budget_ok`는
레거시 거리 근사값이며 구조 통과 판정에서 제외되어 있다. 이 두 값을
PR47 시간 예산 검증 성공의 증거로 사용하면 안 된다. 이번 변경은 해당 지표나
데이터셋을 재설계하지 않는다.

기존 구조 게이트는 기대 장소 수의 하한보다 적으면 실패로 판정한다.
따라서 하한이 1곳 이상인 케이스의 정상적인 `no_feasible` 빈 응답도
judge 호출 전에 탈락한다. 빈 코스의 시간 계약 테스트 통과와 기존 골든셋
품질 평가 통과는 서로 다른 검증이며, 이번 변경에서는 기대 장소 수를 바꾸지 않는다.

실제 품질 비교 전에는 검증된 후보 좌표와 출발지를 갖춘 질의 세트를 준비하고,
같은 평가 기준으로 전후 코스를 채점한 뒤 baseline과 report를 함께 보관해야 한다.
시간 검증은 서버 `time_budget`의 상태와 계산 범위를 기준으로 별도 기록한다.
